# 逐营突围 · Outpost Exodus

单人、2D 卡通废土战役式推进生存策略。向前清理尸群、铺路建营、生产供能；向后撤出人员设备、封关断后，最终完成出口工程并突围。

当前为 **0.9.0-dev**，包含三场独立战役，仍在验证与打磨。长期目标是高度可玩并满足 Steam 发布门槛；目前不能视作正式发行版本。

## 运行

使用 **Godot 4.7.2 stable** 打开 `project.godot`，按 F6/F5 运行项目，或在 Linux 运行：

```bash
chmod +x run.sh
./run.sh
```

未在 PATH 安装引擎时：

```bash
GODOT_BIN=/absolute/path/to/godot ./run.sh
```

启动菜单打开“选择战役”，选择裂谷突围、双桥湿地或山脊换防，按左侧可隐藏、可展开的行动引导推进。需要确认完整规则时，在菜单打开“操作与目标”。

## 当前操作

| 操作 | 默认方式 |
| --- | --- |
| 选择 / 多选 | 左键、拖框、Shift 追加 |
| 移动与交战 | 右键目标区域；X 后左键攻击移动 |
| 镜头 | WASD、中键拖动、滚轮缩放 |
| 小地图 | 左键定位镜头、右键向目标下令 |
| 建设 / 指挥 / 生产 / 训练 | B / V / P / N |
| 编队 | Ctrl+1–4 保存；1–4 选择；Tab 切队 |
| 驻点定位 / 切换运作驻点 | Home / Shift+Home |
| 战术暂停 | Space，暂停时仍可下达指令 |
| 快速保存 / 读取 | F5 / F9 |
| 补给线 / 覆盖范围 | L / O |
| 速度 | + / -，或顶部速度按钮 |
| 菜单 / 帮助 | Esc / H |

23 个主要按键均可在设置中重绑，冲突会提示，界面与帮助随之更新。设置还提供主音量、音乐/音效独立音量、静音、窗口/全屏、分辨率和界面缩放。存档与设置保存在 Godot 的本机用户数据目录，不进入 Git 仓库。

手动存档、自动存档相互独立。每次有效写入会保留上一份有效备份；主文件损坏时，在菜单明确选择“恢复手动备份”。重新开始需确认，并先保存旧局到自动存档。退出前自动保存失败时会保留当前战役，提供返回、重试保存或放弃未保存进度。返回标题前的自动保存失败时，也会保留当前战役并提示重试。

切出窗口或最小化时，进行中的战役会打开暂停菜单，并停止世界音效、清理按住的镜头与拖框动作；返回窗口后需要明确继续。已有的战术暂停、设置或恢复弹窗保持原状态。该流程已在原生X11环境验证，Windows焦点行为仍待实机检查。

## 三场独立战役

| 战役 | 地形与决策 | 已接受0.8实际Linux包的脚本路线 |
| --- | --- | --- |
| 裂谷突围 | 高地与两道关口，先建材或先燃料 | 1580.40秒，5人撤出 |
| 双桥湿地 | 南岸废料、北岸原油，两桥影响转运路线 | 1664.35秒，7人撤出 |
| 山脊换防 | 北侧高脊与南谷绕行，换防时机影响车队安全 | 1774.75秒，6人撤出 |

各关从自己的队伍和库存开始。已接受0.8的同一实际解压Linux包已完成三关：正常引擎时间、标准界面3倍速度、真实20Hz Main主循环；载货撤营时实际存读档，完整模拟/RNG、UI及任务身份保持一致，之后继续真实运输。每关均有3次后营和4次中营交付、付费供能出口、指挥车与幸存者实际抵达。上表是自动指令路线，不代表陌生玩家时长或试玩结论。新0.9正在改进营地信息、分页输入隔离与持续运行验收，仍需自己的导出/整关/长时证据。进行中切关会先确认并把旧局写入自动存档。

## 建造与生产反馈

选择建筑后，预览显示实际供料营地、价格和本地资源缺口。道路会预览整段路线及总价；点击时重新核对当前条件。空闲施工队不足会单独提醒，合法工地仍可先下单等待工人或工程师。预览与实际建筑使用相同落点与验收规则。建设卡片使用与世界建筑一致的图集缩略图；道路和不可用图集保留图形图标。

生产面板显示连续加工状态，区分暂停、未完工、缺少工坊、工坊未供能、缺少原料和正在生产。缺电时会解释本营发电机、成品燃料、道路、覆盖范围或输出优先级问题。小窗口的生产按钮、资源栏和施工预览已调整；B/V/P/N切换面板与点击标签一致，会取消当前放置或目标指令。

驻点卡片新增工作摘要：显示生产、训练或撤收阶段；供能和原料受阻会说明实际原因，筹建中的营地和主动待命也有各自状态。战术暂停时仍可查看本地阻碍，并以暂停符号和“待续”说明作业尚未推进。悬停可展开详情，配合库存与供电量决定下一步。禁用的驻点翻页按钮及卡片空隙会接收界面点击，避免向地图误下命令。

训练面板显示所选营地的本地费用、人口与队列限制、当前进度和停工原因。点击时重新核对库存与供能，失败会给出具体原因。驻点较多时卡片分页，选中营地会自动显示；Shift+Home按当前绑定的驻点定位键循环选择运作中的营地。撤收沿用原有规则：取消本营训练队列并退回每项费用的50%。攻击移动或任务指令待选目标时会持续提示，右键或Esc可以取消。

八个预先生成的原创音效覆盖战斗、拾取、施工、警报和操作结果。音效播放限制为六个世界声部加两个界面声部，暂停、读档和菜单切换不会重播旧事件。现有24秒环境音乐按解码采样数设置循环端点。真实音频驱动和资源回收已验证，最终听感与混音仍需要人工试玩。

## 移动与行动引导

小地图用不同形状标出资源和出口：废料为菱形、燃料为油桶、补给为方箱、出口为旗帜。开始战役后，可见行动引导的当前目标以角框标记；隐藏引导时，该目标标记同步隐藏。小地图左键定位与右键下令继续沿用现有操作。

单位显示在真实固定模拟步之间插值，使移动和步行动画可以随渲染帧更新。插值最多落后一个50毫秒模拟步，不预测未来位置；战斗、资源、命令和存档仍采用真实模拟状态。拖框与点击选择使用画面中的位置；暂停、读档、切关、生成和不连续移动会直接显示当前状态。

开局有人员伤亡时，引导会按存活的步枪兵和工程师调整选择人数。战斗人员全部损失时，会读取实际训练队列与招募条件，提示补充战斗人员、恢复设施供能，或在无法恢复时读取存档或重开；不会继续要求选择已经阵亡的单位。胜利或失败发生时，行动引导会在同一帧更新到终局状态，保留玩家原有的显示、隐藏或禁用选择。

## 当前实际规则

- 高地崖壁阻断通行，坡道、桥梁构成合法跨层路线；单位有体积和分散站位。高地提供射程，实体山体/完整建筑遮挡射击，峡谷上方可以射击，近战不能跨崖攻击。
- 工程队实际领取材料、移动到工地施工，道路可以按路段连续铺设。
- 驻点仓库独立储存建材、补给、燃料及原料，工人和车辆实际搬运。营地卸货口堵住施工或物流时，符合条件的自动到站空闲人员与空车会沿合法路径走到附近等候位，让通道恢复。
- 本地发电与生产消耗真实资源，自动炮塔和军营需要供能。
- 军营训练步枪兵和工程师；有电的驻点招募工人；工坊制造运输车。训练占用时间、材料和人口。
- 后方追兵推进与警报对应；关口阻碍可拖延并被敌人破坏。前往关口另一侧的路线被封锁时，从西向东追击的敌人会尝试从自身可达的西侧接近障碍，再按正常近战规则攻击；有正常通路时沿用原路线。
- 撤收会搬运库存和设备，按接收营地的缺口优先补足燃料/口粮，再装建材；再次点击可紧急弃营、留下未装车资源。
- 出口必须实际施工、供能，并让指挥车辆与人员抵达；等待时间不会自动获胜。
- JSON 存档包含任务、施工、训练、随机状态和物流，坏数据在替换当前战役前验证。

## 代码与资源

- `scripts/construction_rules.gd`：只读施工规划、本地缺口和生产供能诊断。
- `scripts/recruitment_rules.gd`：只读招募条件、本地费用和训练停工诊断。
- `scripts/game_audio.gd`：读取真实事件的有界音效播放，不修改战役或随机状态。
- `scripts/campaign_simulation.gd`：独立状态模拟、寻路、战斗、经济、任务、撤营与存档。
- `scripts/world_view.gd`：实际状态驱动的 2D 卡通绘制与建筑贴图。
- `scripts/render_motion.gd`：只读的单位显示插值；不进入战役存档。
- `scripts/main.gd`：输入、相机、选择、存读档和设置。
- `scripts/hud.gd`：中文 HUD、小地图、建设、生产、训练与指挥界面。
- `scripts/campaign_guide.gd`：依据真实状态观察进度的行动引导。
- `scripts/camp_readout.gd`：只读驻点工作摘要，集中本地生产、训练和撤收状态。
- `scripts/campaign_save_store.gd`：写入验证、文件备份和失败回滚。
- `assets/buildings-atlas.png`：本项目使用图像生成工具制作的透明建筑图集。不是静态关卡截图。
- `assets/fonts/`：Noto CJK Regular 2.004 的10个字体面，字体专用署名、指纹及完整 OFL 1.1随资源附带。
- `tools/generate_audio.py --check`：在内存重现24秒环境音乐并只读比较完整WAV；PCM字节序显式为小端，当前音乐文件未改写。

素材制作方式、来源和待确认事项见[素材台账](docs/asset-inventory.json)及[Steam内容调查草稿](docs/steam-content-survey-draft.md)。草稿尚未提交，也不是平台审核结论；代码及自有美术的最终分发条款仍待确定。

代码、场景和关卡配置适合使用 Git / GitHub 管理。大体积美术源文件和音频后续配置 Git LFS。导入缓存 `.godot/`、测试工作目录与导出构建已忽略。当前已建立本地 Git 仓库，尚未创建或推送 GitHub 远程仓库。可以先用私有仓库开发；上传GitHub不等于公开代码或授予开源许可。开发阶段与代码量估算见[开发计划](docs/development-plan.md)。

## 导出

安装对应的官方 Godot 4.7.2 Linux/Windows x86_64 release templates 后，提交当前源码，执行：

```bash
python3 -m venv work/pe-resources-venv
work/pe-resources-venv/bin/pip install -r tools/build-requirements.txt
GODOT_TEMPLATES_DIR=/absolute/path/to/templates ./tools/export_release.sh
DISPLAY=:0 python3 tools/smoke_native.py
python3 tools/package_builds.py --performance-report /absolute/path/to/native-diagnostics/rendered-benchmark.json
```

工具校验模板摘要、记录导出对应的 Git 提交。Linux 原生启动、截图和忙碌场景完整测量通过后，才能打包原生 Linux/Windows 开发版与源码。Windows 图标/版本由固定版本构建工具写入，并独立校验 PE 结构和代码节不变。构建使用正式运行模板，不附带编辑器；验证状态仍是开发版。Windows 尚未在原生 Windows 系统执行，最低配置和陌生玩家试玩仍未完成。


开发测量使用 `--render-diagnostics`，仅允许全新的专用用户目录，避免碰到正常战役。命令与测量边界见 [验证记录](docs/validation-plan.md)。它会在实际原生游戏中运行 32 友军/100 敌人的控制场景并执行一次真实存档，不代表关卡平衡或最低配置。


整关导出验证使用单独的 `--campaign-validation` 入口，由 `tools/run_native_campaign.py` 从实际 Linux 导出目录启动并核对 EXE、PCK 与构建来源。它保留正常 Main 主循环和 0.05 秒固定模拟步，通过正常界面选择 3 倍速度，只下达公开战役命令，并在载货撤营途中实际存读档。该入口要求全新的隔离目录；Linux 实际进程参数还会拒绝固定 FPS、时间缩放或电影录制等改时钟选项。普通战役、存档和界面不需要 Python；Python 启动器仅用于开发验收。

```bash
DISPLAY=:0 python3 tools/run_native_campaign.py \
  --build-dir "$PWD/builds/linux-release" \
  --mission canyon \
  --isolation-root "$PWD/work/native-campaign-candidate-a"
```

`--prepare-only` 只验证原生启动与少量正常主循环推进，不能证明完成整关。整关结果写入隔离目录的 `output/campaign-validation.json`，进度写入 `output/campaign-progress.json`，启动器独立验收写入 `verification.json`。0.8实际下载包的三关完整路线及忙碌场景测量已通过：普通/战略视图均值59.760686/59.619658 FPS，各3600测量帧加120预热帧，保留真实运输、施工和存档负载。该结果不证明稳定60 FPS、最低配置或一小时持续运行；0.9仍需新包及长时验收。这些自动路线也不替代陌生玩家试玩、Windows或干净机器验收。
