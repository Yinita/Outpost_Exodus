# 开发计划与估算

工作名：逐营突围 / Outpost Exodus。中文和英文均为开发名，尚未完成商标或商店名核查。建议 GitHub 仓库名 outpost-exodus。

## 技术决定

Godot 4.7.2 stable，带明确类型的 GDScript；固定斜俯视 2D、两层地形、显式坡道与桥梁连接。使用成熟引擎承担窗口、输入、资源导入、UI、2D 绘制与导出，项目内实现战役规则。

模拟和显示分离，界面只下达命令。存档保存真实库存、人员、施工、训练、物流和随机状态。先验证完整首关，再增加独立战役与内容。保持单人设计，当前不加入联网、无限世界和自由地形破坏。

## 里程碑

1. 三关规则已实现：小队开路、建设驻点、生产/供能、扩军、资源运输、追兵、撤收、封关、出口胜负。0.12实际解压Linux包已完成Ridge单关技术验收；本版全三图与小时验收仍待完成，0.13还需新包另验，自动通关不代表陌生玩家可玩性。
2. 性能与玩法打磨：0.12普通Ridge的出口施工阶段约48.2 FPS、抵达阶段约57.3 FPS，验收仍为not_assessed。0.13准备加入真实撤收目的营/载货摘要；未测得可确认收益的独立移动实验不合入，原分支和证据保留。同时安排陌生玩家独立上手，检查目标反馈、拥堵与自动任务、难度节奏、存档与失败恢复。
3. 美术与音效：统一卡通素材规格、角色动画、地形边缘、战斗反馈、环境声音、UI 音效和来源台账。0.5已加入八个预生成原创音效及有界播放，最终听感和混音仍需人工验证。
4. 内容与设置：多张独立战役、教程、难度、音量与分辨率/全屏、完整按键配置、无障碍与小地图可读性。
5. 发布验证：继续完成当前包的三图原生战役、载货存读档、分阶段性能与长时间稳定性；Windows实机、干净机器、陌生玩家试玩和Steam账号/商店/发行均未验收。已有Linux单关结果与Windows文件导出不能代替这些环节；账号级提交和商店发布到最后结合实际账号完成。

## 操作与美术实现

相机缩放、小地图、选择编队与快捷键沿用Godot的2D/输入/UI设施，命令统一进入战役模拟层；小地图绘制地形和单位标记，避免再运行一份世界模拟。生产、训练、道路、施工和发电读取本地营地真实库存与队列。前期围绕小队移动、目标选择和短线施工，后期用多营地面板、运输与供能状态、队列、编队和战术暂停承接注意力转移。

0.6通过只读显示插值让单位移动和步行动画在模拟步之间更新，输入选择跟随画面中的位置；战斗与存档仍采用真实状态。切出窗口会暂停并等待明确继续，返回标题也先确认实际自动保存成功。开局伤亡后的引导读取存活战斗人员、训练队列和真实招募条件，降低误导玩家的风险。0.7还改进了封锁障碍前无路可走的敌人接近行为，并让胜负引导在终局帧同步。0.8继续补齐另外两关的实际主循环原生验收，并为建设卡片和小地图补充可读图示。双桥关的真实失败存档还暴露了到站闲置单位堵住付费施工队的问题；模拟层改用自动合法路径等候位清开通道，并以原始存档回归，保留实际运输与成本。已接受0.7的裂谷原生包与性能记录只绑定其实际提交和EXE/PCK；新候选另验。0.8后续同一实际Linux包已通过三关原生整关与盘上续接，但不代表陌生玩家验收。0.9通过只读驻点摘要集中生产、训练和撤收状态，暂停时也保留真实阻碍；Main缓存派生显示，按钮提交仍走原有验收。分页界面范围会接收禁用按钮和空隙点击，避免指令穿透。0.9后续已在同一真实Main中完成七场三图、超过一小时的自动验证；0.12已完成Ridge单关，0.13仍需新包验证，不能沿用旧长测作为当前验收。这些自动/脚本证据仍需新玩家观察来验证操作手感、压力与信息负担。

美术保持固定斜俯视的2D卡通风格：固定角度、统一描边与色板，建筑与角色按可复用图集管理；高低层通过崖壁、阴影和明确坡道表达。先把一关推进、撤营与突围的完整循环打磨到可读，再用相同系统制作其他独立战役。

## GitHub 工作方式

每项功能用小提交记录，main 保持可启动，阶段版打 tag；设计、代码、场景、测试和素材来源都可审阅。正式代码许可证与美术分发许可分开明确。远程仓库未建立前继续本地Git开发。当前尚未创建或推送GitHub远程仓库。建议先建私有仓库，把代码、场景、地图配置、测试和小型运行素材正常纳入Git；大体积美术源文件和音频配置Git LFS。导入缓存、构建目录、存档和密钥排除在外。试玩构建按版本作为发布附件保存。上传GitHub与开源是两个决定；公开前再明确代码许可证与每类素材的分发许可。
