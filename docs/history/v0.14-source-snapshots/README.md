# 逐营突围 · Outpost Exodus

单人、2D 卡通废土战役式生存策略。向前清理尸群、铺路建营、生产供能；向后搬走人员物资、封关断后，最终完成出口工程并突围。

当前源码候选 **0.14.0-dev** 已整合碰撞热点优化与营地操作引导修复，源项目功能及受控原生界面检查通过，尚待本版导出包验证。最近完整接受的开发包是 **0.13.0-dev**：同一实际解压 Linux 包连续完成七场、覆盖三图、超过一小时，并通过实际载货存读档与独立帧统计检查。它仍不是正式发行版本；当前状态见[检查点](docs/current-checkpoint.md)，发行要求见[发布门槛](docs/release-gates.md)。

## 运行

使用 **Godot 4.7.2 stable** 打开 `project.godot`，按 F5 运行。Linux 安装引擎后也可执行：

```bash
./run.sh
```

引擎不在 PATH 时：

```bash
GODOT_BIN=/absolute/path/to/godot ./run.sh
```

在菜单选择一场独立战役，展开行动引导开始。游戏运行不依赖 Python；构建与开发验证工具才使用 Python。

## 三场独立战役

| 战役 | 主要决策 |
| --- | --- |
| 裂谷突围 | 高地与两道关口，先建材或先燃料 |
| 双桥湿地 | 南岸废料、北岸原油，两桥影响转运 |
| 山脊换防 | 北侧高脊与南谷绕行，决定车队换防时机 |

每关从自己的队伍和库存开始。先用小队清路、夺取补给，再连接道路、建设驻点和设施；前方营地需要实际接收物资才能运作。后方追兵持续推进，撤营由运输车真实装卸，紧急弃营会留下未装车物资。出口必须付费施工、持续供能，指挥车与至少4名幸存者实际抵达后才能获胜。

高地崖壁阻挡通行，坡道与桥梁连接各层。高地提供射程，实体山体和完整建筑遮挡射击；近战不能隔崖攻击。道路、工地、本地库存、训练队列、运输和电力均读取同一份真实战役状态。

## 默认操作

| 操作 | 方式 |
| --- | --- |
| 选择、多选 | 左键、拖框、Shift 追加 |
| 移动、交战 | 右键；X 后左键攻击移动 |
| 镜头 | WASD、中键拖动、滚轮缩放 |
| 小地图 | 左键定位、右键向目标下令 |
| 建设、指挥、生产、训练 | B、V、P、N |
| 编队 | Ctrl+1–4 保存；1–4 选择；Tab 切队 |
| 驻点定位、切换运作驻点 | Home、Shift+Home |
| 战术暂停 | Space；暂停时仍可下令 |
| 快速保存、读取 | F5、F9 |
| 补给线、范围 | L、O |
| 速度、帮助、菜单 | + / -、H、Esc |

23 个主要按键可重绑，界面与帮助随之更新。设置提供音量、全屏、分辨率与界面缩放。切出窗口时战役暂停，返回后明确继续。

手动、自动存档相互独立，各有上一份有效备份。坏存档在替换当前战役前验证；保存失败会保留当前局面并提供重试。存档与设置保存在本机 Godot 用户目录，不进入 Git。

## 本版改进与验证边界

- 复用本次移动查询中的首个阻挡体，提前拒绝原算法必然拒绝的尝试；其他情况继续完整原算法。没有跨单位或跨尝试缓存，没有改变移动规则、部队数、模拟步长或随机状态。
- 撤收引导明确源营、接收营、当前选择与真实“紧急弃营”按钮；定位仍只移动镜头。
- 出口立项前按真实最近营地供料，立项后读取工程记录的所属营地。
- 暂停横幅和小窗口悬停读取实际绑定，长键名与动作保持在同一可见行。

源码配对重放在两份真实拥堵存档上记录约13%–14%的模拟步耗时降低；带引导模式约10%。这是顺序交错的源码测量，不能换算成整关 FPS。完整状态/RNG/Guide 跨版本逐步对照、反例回归及合并检查见[碰撞证据](docs/benchmarks/v0.14/first-blocker-rejection/index.json)和[集成证据](docs/benchmarks/v0.14/integration/index.json)。

## 开发与素材

采用 Godot 4 + 带类型的 GDScript，模拟、显示与命令输入分开。玩法、界面、输入、绘制及音频共17个脚本、**8,629物理行**；含测试、诊断和工具共75个自有代码文件、**24,960物理行**。统计含注释空行，不含引擎、第三方库、素材或场景，见[逐文件清单](docs/benchmarks/v0.14/code-size.json)。

建筑图集由图像生成工具制作，角色/地形与部分声音采用程序绘制或生成，Noto 字体附带 OFL 通知。具体来源与待确认事项见[素材台账](docs/asset-inventory.json)。自有代码与美术的最终分发条款仍待确定。

已建立本地 Git，尚未创建或推送 GitHub 远程仓库。可先用私有仓库开发，代码/场景/关卡/测试纳入 Git，大体积美术源文件使用 Git LFS。`.godot/`、`work/`、构建和本机存档不入库；`docs/.gdignore` 避免把文档截图当游戏资源导入。

开发、验证与打包方式见[开发计划](docs/development-plan.md)及[验证计划](docs/validation-plan.md)。旧0.13导出前文档逐字保留在[历史快照](docs/history/v0.13-source-snapshots/index.json)，其中的“待验证”仅描述其当时状态。
