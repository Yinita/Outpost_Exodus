# 开发计划与估算

工作名《逐营突围》/ Outpost Exodus；仓库名建议 `outpost-exodus`，中英文正式名称尚未查重。当前0.14源码候选，最近完整接受的实际开发包为0.13。完整目标与门槛见[发布门槛](release-gates.md)。

## 技术与玩法

Godot 4.7.2 stable + 带类型的GDScript，固定斜俯视2D卡通、显式高地/坡道/桥梁。模拟与显示分开，小地图读取同一份状态，镜头、选择、快捷键与界面下达统一命令。保持单人独立战役；目前不引入联网、无限世界或自由地形破坏。

前期围绕小队移动、目标选择和短线施工；中期管理营地本地库存、生产供能与实际运输；后期通过队列、营地摘要、编队、运输和战术暂停进行多处调度。每关需要形成清路→建营→生产→转运→撤守→付费供能出口的完整循环。

优先用首次玩家观察修正目标反馈、拥堵、供能与弃营判断，再扩展战役内容。自动通过的路线只证明其技术范围。

## 当前规模

0.14的[实际代码清单](benchmarks/v0.14/code-size.json)：17个游戏脚本8,629物理行；包括测试、诊断与工具后共75个自有代码文件、24,960物理行、22,759非空行。物理行含空行和注释，不含引擎、第三方库、美术音频、序列化场景、UID或证据探针副本。

源码热点优化在真实保存态的ABBA测量中降低模拟步耗时约13%–14%，带引导模式约10%；这不是本版FPS或整关性能验收。本版撤收/出口/暂停提示修复已通过源项目及受控GUI回归，接下来对精确新导出包执行完整路线、帧统计和长测。

## 后续工作

1. 冻结并验证0.14原生包，在普通战役中检查拥堵阶段和存读档，不改变真实规则换取帧率。
2. 陌生玩家独立上手，观察早期微操到后期多营地调度，依据实际困惑、失败原因和退出原因调整。
3. 统一角色/建筑/地形/动画与声音，完成人工可读性、听感和无障碍检查；保持素材来源记录。
4. 实际Windows、干净机器与最低配置；完善与交付构建一致的商店材料和内容调查。
5. 在真实Steam项目具备后完成Depot、上传、商店与构建审核、发行。

## 从零规划的参考范围

下表假设1位熟悉游戏开发的全职开发者加AI辅助，从各阶段起点估算，包含必要测试工具，不是当前剩余工期或代码承诺。

| 阶段 | 自有代码 | 参考周期 |
| --- | --- | --- |
| 验证推进与撤守的灰盒 | 3,000–8,000行 | 3–6周 |
| 完整单关Demo | 12,000–30,000行 | 3–6个月 |
| 3–5关、经打磨的首发产品 | 40,000–90,000行 | 12–24个月 |

新增地图主要增加设计、美术、平衡和验证工作，不随关卡数量线性增加代码。生成速度、行数与自动通关都不能直接等同可玩性或发行完成度。

## 版本与素材管理

已有本地Git，尚无GitHub remote或push。建议先用私有仓库：小提交记录功能，main保持可启动，阶段版打tag；代码/场景/配置/测试与素材来源可审阅，大体积美术源文件用Git LFS。构建、导入缓存、开发工作目录和玩家存档不入库。代码开源与美术许可分别决定，当前没有最终自有内容分发条款。

旧版本估算和原始验证过程逐字保留在[0.13源码文档快照](history/v0.13-source-snapshots/index.json)，不把其待验证状态当成当前状态。
